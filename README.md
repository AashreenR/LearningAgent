# AI Learning Coach

A small FastAPI app that uses an OpenAI-compatible chat-completions API to build and track learning plans. Plans, steps, and per-browser chat history are stored in SQLite.

## Run locally

Use Python 3.11 or newer. Create and activate a virtual environment:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Install dependencies:

   ```bash
   pip install -r requirements.txt
   ```

3. Configure the LLM:

   ```bash
   cp .env.example .env
   ```

   Set `LLM_API_KEY` and `LLM_MODEL` in `.env`. The example uses Groq's OpenAI-compatible API URL.

4. Start the server:

   ```bash
   uvicorn main:app --reload
   ```

5. Open <http://127.0.0.1:8000>.

The app creates `learning_coach.db` in this folder on startup. Run tests with `pytest`.

## API

- `GET /health` — basic health response
- `POST /chat` — JSON body: `{"session_id":"...","message":"..."}`
- `GET /plans` — saved plans and ordered steps
- `POST /steps/{id}/toggle` — toggles one step

## V1 limitations

- LLM calls use the synchronous OpenAI SDK. FastAPI runs these synchronous routes in its worker threadpool, but high concurrency will still need explicit timeouts, rate limits, and capacity planning.
- SQLite is suitable for local/single-instance use; multiple app replicas and higher write volume call for a server database and migrations.
- There is no authentication or authorization. Anyone who can reach the app can view and update plans.
- Chat session IDs are browser-local identifiers, not credentials; history has no expiry or retention policy.
- Chat history is sent in full on every turn, so long conversations can increase latency and token cost.
- Plan URLs are generated by the model and are not checked for availability.
- The tool loop is capped at six LLM iterations per request and has no retry or streaming behavior.
